# Windows 输入回传

2026-10-12：Windows 主机服务与真实 Fire TV 的局域网键鼠输入已接入，Steam 大屏幕左右导航获得四次 Windows 注入确认。仍未实现原生手柄，游戏内兼容性未验收。运行方式见 [电视控制闭环](../../docs/tv-host-control-2026-10-12.md)。下文的 loopback 范围描述保留早期模拟器验收背景，当前真实硬件路径绑定协商的主机局域网地址并使用独立会话凭据。

独立 TCP 小消息通道，不共用视频连接。当前面向 Android TV 模拟器：只监听 Windows loopback 的动态端口，由 Android `10.0.2.2` 访问。每次会话使用 Windows CSPRNG 生成 256 位密钥，恢复后旧端口/密钥失效；还未提供真实 Fire TV 的 LAN 配对入口。

客户端即时发送键盘/鼠标按钮的完整状态，100 ms 无操作心跳，序号严格递增。按键边沿进入最多 128 条的队列，短按不能合并掉；相对移动允许合并。主机最多接收 1024 字节消息，验证版本、会话、密钥、序号、数量和数值范围后注入。ACK 只说明 Windows API 接受，不证明特定游戏已经消费输入。

Windows 使用扫描码 SendInput、相对鼠标与滚轮。750 ms 无完整心跳、连接关闭、会话代次变化和停止都会释放本通道持有的键及鼠标按钮。Steam 模式在新会话的第一次操作前尝试聚焦选定窗口，随后允许启动的游戏获得前台焦点，不逐键抢回 Steam；系统拒绝聚焦或输入注入时显示实际异常。不会安装驱动或自动提升权限。

`windows.rs` 是唯一允许 unsafe 的模块，只封装 Win32 C ABI 和系统 RNG；其余模块禁止 unsafe。输入状态进入 core Snapshot，与音画状态独立。输入断开时即使画面继续播放，TUI 的主操作也提供恢复。

```powershell
# 独立状态/范围验证在 workspace tests 中
./scripts/check.ps1
# 显式系统测试，只注入 F24 并读取 Windows 按键状态
cargo run --locked -p sofalink-input --example verify
# 实际 Steam 目标（Steam 已安装且登录）
./start.ps1 -SteamBigPicture
```

当前支持键盘、相对鼠标、三键与垂直滚轮；遥控器方向/确认/返回映射 Windows 方向/Enter/Esc，长按返回退出客户端，菜单键切换统计。虚拟 Xbox 手柄、摇杆/扳机和振动尚未实现，不能把方向键映射算作原生手柄支持。实际游戏的输入兼容性及按键到画面的端到端延迟需逐项验收。

同机模拟器与 Windows 游戏共享前台焦点，验收用 `adb shell input keyevent` 把事件送入 Android，再由回传通道注入 Steam；避免把直接在电脑键盘上操作 Steam 误算成回传成功。真实电视独立运行后没有这种焦点竞争。

2026-10-11 验收：28 项 Rust 测试、7 个合成状态场景通过；实际 F24 注入、TCP 断开及 750 ms 心跳超时释放通过。接入输入后的音视频设备验收取得 141 个健康样本，并通过实际客户端/主机中断、恢复、停止和启动取消。Steam 大屏幕实际接收 Android 短按并打开游戏详情；方向/确认/返回三次短按得到 6 次注入，长按返回结束客户端，TUI 显示输入断开及反馈异常，Enter 恢复后重新确认播放与输入握手。同机 Steam/模拟器运行时帧率会波动，这些结果不等于游戏内持续 60 帧、原生手柄或端到端低延迟验收。
